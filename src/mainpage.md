@mainpage s21_QuotesViewer — визуализатор котировок акций

@section about Описание проекта

s21_QuotesViewer — настольное приложение для анализа исторических котировок
акций. Программа загружает данные из CSV-файла (дата и цена закрытия),
отображает их на графике и строит поверх исходных данных два варианта
сглаженной кривой: интерполяционный кубический сплайн и аппроксимирующий
полином, полученный методом наименьших квадратов (МНК). Полиномиальная
аппроксимация допускает прогноз значения цены на M дней вперёд за пределами
загруженного периода.

Помимо построения графиков, приложение позволяет вычислить точное значение
кривой в произвольный момент времени: пользователь указывает дату и время
(с точностью до секунды), а модель возвращает значение сплайна или
аппроксимирующего полинома в этой точке. Дробная часть суток учитывается
при вычислении, что даёт плавное изменение результата внутри одних суток.

@section features Возможности

- загрузка котировок из CSV-файла с валидацией и сортировкой по дате;
- отображение исходных точек данных в виде графика;
- интерполяция кубическим сплайном (проходит точно через все точки данных);
- аппроксимация полиномом заданной степени (от 0 до N − 1, где N — число
  записей) методом наименьших квадратов;
- прогноз: график полинома продолжается на M дней вперёд (M ≥ 1);
- вычисление значения сплайна и полинома в произвольный момент времени
  с учётом времени суток;
- информативные сообщения об ошибках на русском языке (файл не открылся,
  некорректная строка CSV, дубликат даты, недопустимая степень полинома и т.д.).

@section architecture Архитектура

Проект построен по шаблону MVC (Model–View–Controller). Каждый слой
изолирован: модель не знает о Qt и интерфейсе, контроллер не содержит
бизнес-логики, а вид обращается к модели только через контроллер.

@verbatim
┌─────────────────┐      ┌───────────────────┐      ┌──────────────────┐
│      View       │      │    Controller     │      │      Model       │
│   (Qt6 Widgets) │─────▶│  преобразование   │─────▶│   данные и       │
│ main_window     │◀─────│  типов и вызов    │◀─────│   алгоритмы      │
│ plot_widget     │      │  методов модели   │      │                  │
└─────────────────┘      └───────────────────┘      └──────────────────┘
@endverbatim

| Компонент | Файлы | Ответственность |
|--------------------|--------------------------------|--------------------------------------------------|
| Model | model/model.{h,cpp}, model/model_types.h | фасад: загрузка данных, построение графиков, вычисление значений |
| CsvLoader | model/csv_loader.{h,cpp} | чтение и валидация CSV-файлов |
| CubicSpline | model/cubic_spline.{h,cpp} | интерполяция кубическим сплайном |
| LeastSquares | model/least_squares.{h,cpp} | аппроксимация полиномом по МНК |
| Controller | controller/controller.{h,cpp} | посредник между видом и моделью |
| View | view/main_window.{h,cpp}, view/plot_widget.{h,cpp} | окно приложения и отрисовка графиков (Qt6) |

@section model Устройство модели

Модель оформлена как независимая статическая библиотека `model` без
зависимостей от Qt, что позволяет собирать её и тестировать отдельно от
графического интерфейса.

- **CsvLoader** читает файл построчно. Строки, начинающиеся не с цифры,
  считаются заголовком и пропускаются; каждая строка данных разбирается в
  пару «дата — цена закрытия». Загрузчик требует не менее двух записей,
  уникальность дат и корректность каждой строки; при ошибке возвращается
  сообщение с номером проблемной строки. Итоговый список сортируется
  по возрастанию даты.
- **CubicSpline** строит интерполяционный кубический сплайн с естественными
  граничными условиями. Коэффициенты `c` находятся решением трёхдиагональной
  системы методом прогонки. Сплайн проходит точно через все узлы, значения
  вне диапазона данных клампятся к крайним точкам.
- **LeastSquares** подбирает коэффициенты полинома заданной степени по МНК.
  Аргумент нормируется в отрезок [-1; 1] для устойчивости, составляется
  матрица нормальных уравнений, которая решается методом Гаусса–Жордана
  с выбором главного элемента. Если система вырождена (например, степень
  завышена относительно данных), построение завершается ошибкой.
- **Model** — фасад над перечисленными компонентами: хранит загруженные
  данные, строит результирующие графики (возвращает равномерно
  распределённые точки) и делегирует точечные вычисления сплайну или
  полиному.
- **Result<T>** — тип-обёртка, вынуждающий вызывающий код явно обрабатывать
  ошибки: результат либо содержит значение, либо текст ошибки.

@section csv_format Формат входных данных

Входной файл — текстовый CSV с разделителем «запятая», две колонки:

@code
date,close
2024-01-01,100.0
2024-01-02,101.5
2024-01-03,99.8
@endcode

- дата строго в формате `YYYY-MM-DD`, значение цены — вещественное число;
- первая строка может быть заголовком — она пропускается;
- записей должно быть не менее двух, даты не должны повторяться;
- завершающие пробельные символы (в том числе CRLF) допускаются,
  любой другой «мусор» после значения считается ошибкой.

@section build Сборка

Зависимости: компилятор с поддержкой C++20 (`std::format`) — GCC 13+ или
Clang 17+, CMake ≥ 3.16, Qt6 (компонент Widgets). Для сборки тестов Qt не
нужен: библиотека `model` и тесты собираются без него, а исполняемый файл
`quotes_viewer` пропускается, если Qt6 не найден.

Через Makefile (обёртка над CMake):

@code
cd src
make            # конфигурация и сборка
make test       # сборка и запуск модульных тестов
make style      # проверка форматирования кода (clang-format, стиль Google)
make clean      # удаление каталога сборки
@endcode

Напрямую через CMake:

@code
cmake -S src -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
@endcode

Параметры конфигурации:

| Параметр | По умолчанию | Назначение |
|---------------|--------------|-----------------------------------------------|
| BUILD_TESTS | ON | сборка модульных тестов модели (GTest) |

@section tests Модульные тесты

Модель покрыта модульными тестами на Google Test (GTest) — тестируется
только model-слой, контроллер и вид тестами не охватываются. Всего 49
тестов в четырёх наборах:

- `csv_loader_test` — 13 тестов: успешная загрузка (с заголовком и без,
  CRLF, пробельные символы), сортировка по дате, а также все сценарии
  ошибок (отсутствующий файл, пустой файл, одна запись, некорректная
  строка с верным номером, дубликаты дат, невозможные даты, мусор после
  значения, неверный разделитель);
- `cubic_spline_test` — 8 тестов: отказ на вырожденных входных данных,
  точная интерполяция в узлах, точное воспроизведение линейных данных,
  клампинг за пределами диапазона, гладкость (C¹) на внутренних узлах;
- `least_squares_test` — 8 тестов: валидация степени, полином нулевой
  степени как среднее, точное воспроизведение линейных, квадратичных и
  кубических данных, поведение на константных данных, экстраполяция;
- `model_test` — 20 тестов: поведение пустой модели, загрузка и замена
  данных, маппинг дат в дни от эпохи, интеграция сплайна и аппроксимации
  с фасадом, валидация всех аргументов, согласованность `ApproxValueAt`
  с началом графика `ApproxGraph`.

GTest подключается автоматически: используется системный пакет, а если он
не найден — FetchContent скачивает и собирает Google Test 1.15.2
(пинуется по SHA-256). Запуск:

@code
make test                                # или: ctest --test-dir ../build
./build/tests/model_tests                # прямой запуск бинарника тестов
@endcode
